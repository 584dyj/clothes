# 衣橱助手

> 记录衣物、穿搭与开销的微信小程序，内置 AI 穿搭助手、购买评估、闲置月报与天气穿搭提醒。

基于原生微信小程序 + 微信云开发（CloudBase），AI 能力由服务端代理调用兼容 chat completions 接口的模型服务（默认 DeepSeek）。

## 功能特性

- **衣物管理**：照片、类别、尺码、颜色、品牌、季节、价格等字段；新增与编辑时季节单选，兼容读取历史多季节记录；支持照片裁剪与旋转、单件拍照 AI 预填、保存并继续添加及可选沿用品牌和季节、最多 9 张的批量拍照建档，以及对所选待保存衣物统一设置品牌和季节
- **品牌输入建议**：单件编辑与批量建档均可搜索本人已有衣物的品牌，忽略大小写做包含匹配，点击建议填入，也可输入新品牌。服务端聚合去重后只返回品牌列表，前端缓存并在本地匹配，无需读取完整衣橱或维护独立品牌集合
- **衣物预览与关联穿搭**：衣橱、分类页与月历购买记录点击衣物卡片先进入只读详情：大图点击全屏预览，下方按套展示包含该衣物的已保存穿搭及套内单品（本件带角标），右上角编辑进入原表单；编辑页删除后自动回退来源列表
- **造景贴纸**：从「我的」页进入独立库存与心愿单，支持图片网格、封面建档、普通编辑、转为库存、标记已拼贴、撤销完成和删除；主页统计显示拥有、已贴、未贴与开销，开销按全部已购款的单价 × 数量计算，不计入衣橱统计总花费；已拼贴作品照支持点击全屏预览
- **衣橱浏览**：19 个类别分栏，包含独立的马甲类别；支持多维筛选、名称搜索、时间与价格排序
- **我的穿搭**：无日期的搭配本，跨分类选择 1 至 100 件单品，备注选填，名称留空自动生成；卡片可选「今天穿了」记录当日实穿，单纯保存搭配不计穿着次数
- **日常推荐与穿着计划**：从穿搭页进入「明日穿什么」，按天气和近期推荐、实穿记录选择衣物。「换这件」仅替换同类别的适温衣物，配饰保持子类别，无替代时明确提示并保留当前选择；「换一套」可调整主体类别，衣橱暂缺上装或下装时也可轮换已有主体。点击照片可全屏预览，卡片其他区域切换勾选。普通刷新保留当前方案，天气、城市、衣橱或近期实穿记录变化时重新匹配，站内获取推荐不消耗消息订阅次数。可勾选保存穿搭、按显示日期安排穿着；当天从「今日计划」带入衣物，按实际情况调整并确认实穿，计划本身不累计穿着次数
- **AI 穿搭助手**：对话式穿搭建议（文字 SSE 流式回复 / 拍照多模态问答），可指定衣橱单品为搭配核心；会话支持多轮上下文、改名、删除
- **购买评估**：输入品类、颜色、季节、价格和用途，规则引擎先出结论；附候选照片时由视觉模型对照本人衣物复核，模型只能在预算硬约束内调整一级结论
- **穿搭日历**：月历统一合计衣物购买、账本与贴纸购买开销，展示每日穿搭计划与标记
- **实穿记录管理**：简化录入路径。日期摘要条默认今天、点按补记过去（不可记未来），备注为网格下方单行可选输入，「保存并记为穿搭」为主按钮下文字链接；支持带入上次实穿或搭配、快捷入库保留草稿、历史编辑删除；同账号同日同衣物集合服务端原子判重
- **独立账本**：非衣物开销（洗护、修改等）分类记录，并入月历与统计
- **数据导出与恢复**：从「我的→数据备份」导出六类业务记录及原始图片，支持校验后恢复到当前账号；保留已有记录，补充缺失记录，同一备份可重复恢复
- **穿着与搭配统计**：穿着频次榜、按当前搭配引用次数计算的「常被搭配」榜、闲置榜及分类 / 品牌 / 季节分布；闲置榜与月报共同使用近期有效实穿或近 90 天新建搭配作为活动信号，两者均无时提示记录不足
- **闲置月报**：按月推送拥有满 90 天且近 90 天未记录穿着或搭配的衣物，购买日期缺失回退入库时间；搭配活动按 `createdAt` 判断，仅编辑旧搭配不刷新活动日期；按账号 + 月份幂等。在「我的→提醒」常驻显示月报剩余次数，通过「增加1次月报提醒」补充授权，次数达到 12 时停止新增，消息点击后进入统计分析
- **天气穿搭提醒**：有可用次数时每晚 21:30 收到明日天气与基础衣橱建议，每日最多一条；推送落地页展示推荐衣物，可勾选保存搭配并按显示日期安排穿着，过期推荐保留查看和保存搭配能力。在「我的→提醒」设置城市、查看天气剩余次数并补充授权，达到 12 时停止新增，天气与月报次数独立；城市支持自动定位、地图选点与手动输入，未设城市的账号不推送也不消耗额度
- **提醒取消**：两组增加按钮旁均有「取消提醒」，直接清零对应次数，互不影响，可重新授权从 1 次积累；0 次禁用，失败保留原次数
- **连续打卡**：个人页展示连续记录天数和本月打卡天数，今天尚未记录时可从昨天起计算连续天数
- **数据安全**：所有业务数据经云函数鉴权（集合客户端全禁）、上传票据归属校验、登录 / 注册失败限流、注册码事务化消费

## 技术栈

| 层 | 技术 |
| --- | --- |
| 客户端 | 原生微信小程序（WXML / WXSS / JS，无框架无构建） |
| 后端 | 微信云开发云函数（Node.js，wx-server-sdk） |
| 数据库 | 云开发文档型数据库（当前代码涉及 15 个集合，客户端权限全禁） |
| AI | 服务端 HTTPS 代理 chat completions 接口，支持文本、流式 SSE 与多模态视觉 |
| 测试 | Node.js 内置 `node --test`，包含单元测试与故障回归 |

## 项目结构

```text

components/                     wheel-picker、multi-picker、batch-panel
cloudfunctions/
  auth/                         认证、数据 CRUD、推荐、对话、识别、购买评估、订阅
  chat-stream/                  HTTP 云函数：验证身份后代理模型 SSE 流式对话
  monthly-report/               定时云函数：闲置月报订阅消息推送
  weather-alert/                天气穿搭提醒、城市解析、站内日常推荐
utils/                          云环境配置、数据缓存、认证、日期、Markdown 渲染与页面交互辅助

```

## 快速开始

以下是从零拉取代码到本地跑起来、并部署到自己的微信云环境的完整步骤，适用于协作者。

### 环境要求

- Git
- 微信开发者工具（基础库 ≥ 3.15.2）
- 一个已开通微信云开发的小程序 AppID（位置能力需按主体 / 类目申请，见第 7 步）
- Node.js ≥ 18（运行测试与工具脚本）

### 1. 拉取代码

```bash
git clone <仓库地址> clothes
```

### 2. 导入项目并绑定 AppID

1. 微信开发者工具「导入项目」选择仓库目录；
2. 在 `project.config.json` 中把 `appid` 换成你自己的 AppID；
3. 详情 → 本地设置确认基础库 ≥ 3.15.2。

### 3. 开通云开发并替换环境 ID

1. 工具栏「云开发」首次打开即开通，得到环境 ID（形如 `cloud1-xxxxxxxx`）；
2. 修改 `utils/config.js` 中的 `CLOUD_ENV` 为你的环境 ID。客户端所有云调用（含 `chat-stream`）统一从这里取值，只需改这一处。

### 4. 创建数据库集合

在云开发控制台创建以下集合，权限统一设为「所有用户不可读写」（客户端一律经云函数鉴权）：

```
clothes  outfits  users  invite_codes  auth_attempts  upload_tickets
cleanup_jobs  expenses  wear_records  outfit_plans  ai_chats
wardrobe_meta  ai_cache  subscriptions  stickers
```

创建以下唯一索引，保障账号绑定和注册码的一致性：

| 集合 | 唯一索引 |
| --- | --- |
| `users` | `username`、`openid` 分别创建升序唯一索引 |
| `invite_codes` | `code` 升序唯一索引 |
| `auth_attempts` | `key` 升序唯一索引 |

复合查询涉及 `_openid`、`createdAt`、`_id` 排序；`wear_records` 还涉及 `date`，`ai_chats` 涉及 `updatedAt`。按云控制台的查询提示创建对应组合索引。迁移已有数据时，先检查重复数据再创建唯一索引。

云存储需另行配置创建者读写权限，并核验不同微信身份之间的图片访问隔离。服务端上传票据校验不能替代云存储权限。

### 5. 部署四个云函数

对每个云函数目录「上传并部署：云端安装依赖」（或本地 `npm install` 后上传全部文件）：

| 函数 | 说明 |
| --- | --- |
| `auth` | 核心认证、数据 CRUD、对话、识别、购买评估、订阅；超时建议 60 秒 |
| `chat-stream` | **HTTP 云函数**，Node.js 18+；保持 `scf_bootstrap` 为 LF 换行及可执行权限，超时 ≥ 45 秒 |
| `monthly-report` | 定时触发器 `0 0 9 1 * * *`（Asia/Shanghai 每月 1 日 09:00），超时 300 秒 |
| `weather-alert` | 定时触发器 `0 30 21 * * * *`（Asia/Shanghai 每日 21:30），超时 300 秒；同时提供城市设置和站内日常推荐接口 |

两个定时函数均需在云函数配置中开通「订阅消息」的 `subscribeMessage.send` 权限，并通过微信 IDE 的云开发控制台配置定时触发器。Cron 按秒、分钟、小时、日、月、星期、年填写；本地 `config.json` 仅作配置声明。配置后核对触发时区、运行日志和消息送达，避免重复配置调度。

升级现有环境时，先部署配套云函数，再发布客户端。日常推荐依赖 `weather-alert`，购买评估、数据备份、保存重试保护与品牌列表接口依赖 `auth`；完整部署 `auth` 目录（含 `backup.js`）。这些功能复用现有集合，无需新增集合或迁移品牌数据。

### 6. 配置环境变量

以下变量只存在于各云函数的环境变量中，**不写入代码库**：

| 变量 | 部署位置 | 说明 |
| --- | --- | --- |
| `AI_API_KEY` | `auth`、`chat-stream` | 模型服务密钥 |
| `AI_API_BASE` / `AI_MODEL` | `auth` | 模型接口地址 / 模型名（兼容 chat completions） |
| `CHAT_STREAM_SECRET` | `auth`、`chat-stream` | 流式凭证签名密钥（≥ 32 随机字符，两函数保持一致） |
| `CLOUDBASE_APIKEY` / `CLOUDBASE_ENV_ID` | `chat-stream` | 服务端凭证消费所需 |
| `REPORT_TMPL_ID` | `monthly-report` | 月报订阅消息模板 ID |
| `WEATHER_API_KEY` | `weather-alert` | 高德 Web 服务 key（地理编码 + 逆地理编码 + 天气） |
| `WEATHER_TMPL_ID` | `weather-alert` | 天气订阅消息模板 ID |
| `WEATHER_API_HOST` | `weather-alert` | 可选，高德接口地址，默认 `https://restapi.amap.com` |

订阅消息模板需在 mp 后台「功能 → 订阅消息」申请，并把模板 ID 同步到 `pages/profile/profile.js` 顶部的 `WEATHER_TEMPLATE_ID` / `REPORT_TEMPLATE_ID` 常量。

### 7. 位置能力（天气城市自动定位）

天气城市自动定位依赖两项平台配置，缺一不可：

1. **隐私保护指引**：mp 后台声明「位置信息」，用途如「自动获取所在城市以提供天气提醒与穿搭建议」，并随版本提审；
2. **接口权限**：mp 后台「开发管理 → 接口设置」按实际主体和类目申请位置接口权限，并核验 `getFuzzyLocation` 与 `chooseLocation` 的可用性。

接口权限或隐私声明未生效时，自动定位和地图选点可能不可用；可通过手动输入城市使用天气功能。权限状态以你的小程序后台为准。

`app.json` 已声明 `permission.scope.userFuzzyLocation` 与 `requiredPrivateInfos: ["getFuzzyLocation", "chooseLocation"]`，无需额外修改。

### 8. 添加注册码并登录

向 `invite_codes` 集合插入一条一次性注册码（`code`、`used: false`），编译后从启动页进入登录页注册（注册即绑定当前微信 openid，此后自动登录）。

### 9. 验证跑通

```bash
node --test
```

微信开发者工具编译无报错后，可依次验证：注册登录、录入衣物、AI 助手对话、设置天气城市、获取明日推荐、调整衣物并安排穿着。到计划当天，从穿搭页「今日计划」确认或调整实穿；天气和月报消息需另行申请订阅授权。

## 数据与使用边界

- 推荐由经验温度规则和近期记录筛选，不能保证个人体感或鞋子的防水性能；候选不足时会说明缺项。
- 马甲按季节匹配，作为独立叠穿层搭配内层上衣或连衣裙，不替代低温所需的保暖外套；针织、羽绒及西装马甲均可归入此类。
- 推荐、保存搭配和安排计划均不自动计入实穿，穿着次数仅来自有效实穿记录；未记录穿着无法证明从未穿过。
- 推荐页同一日期、版本和衣物选择的保存重试复用服务端回执；穿搭已保存而计划失败时，可重试完成计划。
- 单件新增可选择“保存并继续”，成功后留在新增页；可主动勾选沿用品牌、季节，仅在本次连续添加中生效，尺码沿用已有记忆，价格和购买日期每件清空。失败保留表单。批量页先勾选衣物再设置品牌或季节，未设置字段保持原值，应用后仍需保存。新增衣物重试复用保存回执，避免响应丢失造成重复记录；使用前先部署完整 `auth` 再更新客户端。
- 单件及批量照片提供“裁剪 / 旋转”入口，进入小程序内的 3:4 可视裁剪框，与衣物预览比例一致；支持拖动、双指缩放、90°旋转和重置，框内内容即最终照片。云端图片先下载到本机，确认后生成 JPEG 裁剪图，取消保持原图；读取失败显示具体阶段。批量编辑后重新上传识别，保留已填写字段。
- 衣物价格可留空，保存为 `null`；明确填写的 `0` 表示 0 元。详情、金额排序、统计、月历与备份恢复保留这一区别。旧版本保存的 `0` 无法判断是否曾经留空，沿用原值，可手动修正。
- 衣橱统计展示当前衣物的已填金额及与账本的合计，贴纸已填开销单独统计；月历按日期合并三类已填开销。缺价记录保留并提示，金额不包含缺失值。统计基于现存记录，编辑或删除会改变结果，不代表完整历史消费。
- 购买评估的月预算使用完整衣物与账本记录，按 Asia/Shanghai 的当前月份和整数分合计，包含一级「其他」衣物，不使用推荐画像的采样结果。本月缺价或未填购买日期的衣物会提示可能低估开销；缺失或错误的历史记录无法推断为真实花费。
- AI 对话、识别和视觉复核会将相关文字或照片发给配置的模型服务。部署前请确认服务商的数据政策和调用费用，密钥仅保存在云函数环境变量中。

## 备份与恢复

1. 在「我的→数据备份」选择「导出备份（含图片）」，完成后点击「发送备份文件」另存。导出期间请勿在其他设备编辑数据。
2. 备份为版本化的 `.jsonl` 文件，包含衣物、穿搭、实穿、计划、账本、贴纸及实际图片文件。图片分块存储并校验长度与 MD5，恢复不依赖原云存储文件继续存在。文件未加密，包含私人数据，请妥善保管。
3. 通过微信聊天选择备份文件，完整校验格式、业务字段、图片和结束标记后，再确认恢复。账号凭据、注册码、订阅授权、个人资料、AI 对话和缓存不在备份范围。
4. 恢复补充缺失记录，保留当前已有内容。跨账号或环境时重新映射记录 ID、图片与关联引用；同一来源的记录重复恢复不会重复新增。已有记录不会被旧备份覆盖。
5. 恢复分批提交。中断或响应丢失后可重新选择同一备份重试，已提交的批次会保留；实穿组合冲突会明确报错，不覆盖现有记录。历史失效引用会保留，已清空的搭配也可恢复。

导出文件包含实际图片，较大衣橱需要足够的设备存储与上传时间。本机待发送文件不等于异地备份，请确认文件已成功另存。
